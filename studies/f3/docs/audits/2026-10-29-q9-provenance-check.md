# Q9 provenance check: Hooper et al. (2026) deposited clock files

29 October 2026. Codex. This is a bounded provenance and consistency check,
not a reanalysis of the molecular clock.

## Material checked

The local, git-ignored divergence-time archive was checked without modifying
it:

`data/external/local/deposits/hooper2026-spore-evolution/03. Divergence Time Estimation.zip`

Its SHA-256 remains
`79fd06812eff714e32a566cadc1c15844640e0a150b4504a07999d2cef957a25`, matching
the repository manifest and the 44-member inventory. The supplied inputs are:

- `prior.ctl`: `usedata = 0`, independent-rates clock (`clock = 2`);
- `posterior.ctl`: `usedata = 2`, independent-rates clock (`clock = 2`);
- both controls use `burnin = 50000`, `sampfreq = 250`, `nsample = 5000` and
  `seed = -1`;
- `Fossil_Calibrations_HooperNP.txt` contains 69 fossil-calibration `B(...)`
  expressions, all with lower and upper tail arguments `0.01,0.01`.

The root constraint is separately `B(9.85,18.56,0.025,0.001)`. The control
files therefore do not implement a uniform 2.5% tail for the fossil
calibrations described in the paper. The Supplementary Information gives the
published tracheophyte calibration as 420.7–431.2 Ma (C_24); the deposited
calibration tree contains rounded values in its time-unit representation,
including `4.21` for the corresponding lower bound.

## MCMC sampling semantics and corrected summaries

The official PAML history states that MCMCtree starts taking samples and
writing them to the MCMC file only after burn-in
([PAML history](https://github.com/abacus-gene/paml/blob/master/doc/pamlHistory.txt)).
The official control template defines `burnin` as discarded iterations and
`nsample` as collected samples
([MCMCtree control template](https://github.com/abacus-gene/paml/blob/master/src/mcmctree.ctl)).
The deposited R script reads each chain directly with `read.delim`, without a
second burn-in filter.

Each deposited chain has 5,001 saved rows including the initial saved row and
5,000 sampled rows, with `Gen` values 1 through 1,250,000. The primary
summary therefore uses all 5,001 rows, matching the deposited R reader. The
previous `Gen > 50000` selection is retained only as a labelled sensitivity
summary (4,800 rows); it is not the primary estimate.
This corrects the preliminary extraction reported in Correspondence messages 2490–2494;
message 2495 records the correction explicitly.

Primary empirical summaries after converting time units to Ma:

| node | run | rows | mean | empirical 2.5% | median | empirical 97.5% |
|---|---|---:|---:|---:|---:|---:|
| 184, crown Embryophyta | prior | 5,001 | 441.67 | 428.10 | 441.92 | 453.82 |
| 184, crown Embryophyta | posterior | 5,001 | 453.70 | 450.05 | 453.68 | 457.36 |
| 185, crown Tracheophyta | prior | 5,001 | 427.24 | 421.08 | 427.76 | 431.35 |
| 185, crown Tracheophyta | posterior | 5,001 | 430.53 | 427.82 | 430.79 | 432.02 |

For reference, the posterior `Gen > 50000` sensitivity gives 453.69 Ma
(450.04–457.34) for node 184 and 430.53 Ma (427.82–432.03) for node 185.

## Independent output-tree clade and HPD check

The deposited posterior NEXUS tree has 177 tips and 176 internal nodes. Its
95% HPD annotations were parsed independently and matched to the calibration
nodes by complete leaf-set equality:

| calibration node | output-tree node | exact clade match | output-tree 95% HPD |
|---|---:|---|---:|
| 184, crown Embryophyta | 184 | yes (154 leaves) | 449.91–457.21 Ma |
| 185, crown Tracheophyta | 185 | yes (101 leaves) | 428.27–432.29 Ma |

This confirms the focal clade identity and records the tree's own HPD values;
it does not replace the chain summaries or establish which historical run
generated the output tree.

## Q9 finding and traceability limit

The archive supports the following qualified statement:

> The supplied posterior output is internally compatible with the published
> crown-embryophyte summary, while the supplied calibration input uses 1%
> fossil-calibration tails rather than the 2.5% tails described in the paper.

The provenance discrepancy remains unresolved. The controls reference
`mcmc_prior.out` and `mcmc_posterior.out`; the traceability check now compares
those basenames against both exact and full ZIP-member paths, and finds no
matching archive members. The output files are named `old_version`, contain no
run log or control-file hash, and the included R plotting script reads the
output tree and chain from a historical absolute working directory without
recording the MCMCtree invocation. Matching ages therefore remain consistency
evidence only. No supplied input or output was changed here, and no historical
control/output linkage is claimed.
